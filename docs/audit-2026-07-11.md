# Ops End-to-End Logistics Audit — 2026-07-11 (event morning, doubles day)

Focused end-to-end audit of the four ops-side flows a volunteer/HQ actually
runs day-of, traced device → `store.js` → `pushToSheet` → Apps Script
(`ops-write-back.js`) → sheet tab → public read:

1. **Doubles check-in** (`sections/CheckIns.jsx`)
2. **Payments** (`sections/Payments.jsx` + `CashDrawer.jsx`)
3. **Compass draw** (`sections/Seeding.jsx` + `lib/draw.js` + `lib/compass.js`)
4. **Scores** (`sections/Scores.jsx`)

`docs/next-audit-handoff.md`. Performed against
`claude/logistics-audit-e2e-7ugp4x` (branched from `main` @ `0469ca7`).

## 1. What's verified correct (end-to-end)

- **Compass numbering contract holds.** The ops engine (`lib/draw.js`
  `graphFor`) and the public sheet renderer (`lib/compass.js`
  `buildCompassModel`) both derive from the *same* `graphFor` / `seedOrder`
  and agree byte-for-byte on the numbering: East 1-15, West 16-22, North
  23-25, South 26-28, play-ins 29+, consolation 29+pIns+. Traced pIns = 1/3/8
  and short fields (15 teams) by hand — host lines, play-in feeders (`W of
  M29…`), byes-to-top-seeds, and the walkover cascade all line up on both
  sides. The public board overlays ops-posted rows by `num+event`, so scores
  entered on the Scores tab land on the correct compass line.
- **Winner advancement is derivation, not mutation.** `resolve()` re-derives
  every downstream slot from the static feeder graph on each render, and
  `setResult` invalidates all transitive downstream results — re-marking a
  doubles winner can't strand a stale name in a later round. Marking a winner
  on the Draw board *or* the Scores tab routes through the same
  `markBracketWinner` → `applyBracket`, so the bracket, the flat Match Order
  queue, and the public board advance together, and the corrupt-bracket guard
  (`safeBracket`) drops an unmappable persisted draw instead of black-screening.
- **Payment math is consistent across the three surfaces.** Check-ins,
  Payments, and Command Center all treat "paid" as including Comped;
  `collected = (paid − comped) × $40` counts every non-comped method,
  `outstanding` excludes comps, and the cash drawer's `expected = float + net
  cash in` is separate from (never double-counts) the all-method revenue view.
  Cash change is handed back out of the drawer, so an entry nets $40 and the
  drawer reconciles.
- **PII boundary intact on every new path.** `SYNCED_OVERLAY_FIELDS` limits
  what leaves the device to check-in/payment/shirt state; `regPay` (form
  payment intent) is served **only** through the token-gated `mode=opsdesk`
  read and stripped from every public path (`filterRosterCols_` + the
  Cloudflare Function); OpsDesk/OpsWalkups/OpsDraw are absent from `READABLE`;
  seed pushes remain Name/Event/Rank-only, enforced by the fixed row shape in
  `writeSeeds_`. Committee `notes` never cross the wire.
- **Cash drawer is deliberately local, payment status syncs.** One physical
  box → one device ledger (never synced, so two phones can't drift one
  drawer); the `paid`/method *status* still syncs to every device. This is the
  correct split and the copy says so.

## 2. Findings

### 🟡 FIXED — Scores & Seeding always opened on "Sunday Singles"
`Scores.jsx` and `Seeding.jsx` hardcoded `useState('Singles')`. On the doubles
day (today), a courtside volunteer opening **Scores & Courts** landed on an
empty **Sunday Singles · Live now** screen — reads as "scoring is broken" during
the moment it can't be. *Fix:* new `defaultEventForToday()` in `lib/schedule.js`
matches today's local date to a first-serve anchor and defaults both tabs to the
day's own event (Doubles today, Singles Sunday). Deliberately targeted — every
non-event day keeps the prior `Singles` default, so draw-week setup is
unchanged. Both tabs still have the event toggle. (lint/build clean; helper
unit-checked for Sat/Sun/setup/post-event.)

### 🟡 The "Synced across devices" copy is only true if the Apps Script is current
The multi-device desk sync, `regPay`, the scholarship-meter/schedule/config
pushes, and the field-lock flag **all silently no-op** against a stale deployed
Apps Script (the `opsdesk`/`config`/`status` handlers and `rosterPayIntent_`
must be live). But Check-ins/Payments now assert **"Synced across devices
(~30s)"** in-app. If the deployed script predates the sync handlers, every
device is back to the old local-only model while the UI promises sync — the most
dangerous version of a silent failure (an off-site HQ trusting a check-in count
that isn't actually shared). There is still no in-app deploy indicator (carried
forward from 2026-07-07 §3.1). **Manual action §4.1 is a hard pre-play gate this
year, not a nicety** — the sync it enables is now load-bearing.

### ⚪ Desk shirt-size override is an incomplete pipeline (no writer)
`shirtSize` is in `SYNCED_OVERLAY_FIELDS`, merged by `pullDesk`, and read as
`overlay.shirtSize || registered shirtSize` in **both** Check-ins (the size
badge) and Merch (demand counts) — the HANDOFF documents it as the desk
size-correction override. But **no UI ever writes `overlay.shirtSize`**, so the
override is unreachable: a wrong size printed on a registration can't be
corrected at the desk, and the fallback (registration size) always wins.
Low impact (nothing crashes; the registration size still shows), but the
promised correction doesn't exist. *Recommendation:* add a small size `Select`
to the check-in shirt badge writing `setOverlay(name, { shirtSize })` — the sync
field and both read sites already exist, so it's just the missing input. Left
out of this commit to keep the event-morning diff surgical.

### ⚪ Un-marking a hand-added match winner leaves `status: 'final'`
On a **non-engine** (hand-added) Scores row, tapping the winner again clears
`winner` but keeps `status: 'final'` (`Scores.jsx setWinner` else-branch). The
public board treats a final-with-no-winner as not-final (`isFinal` needs a
winner side), so it's cosmetic and only affects hand-added rows (the engine owns
every real bracket match). Note, not a blocker; set status back via the row's
Status select.

### ⚪ Carried forward (still accepted for this year)
- **Last-writer-wins on synced surfaces** is now per-field for the desk overlay
  (two devices can edit different fields for one person safely), but seeds still
  drop-and-replace per event and aces overwrite as absolute totals — the
  one-device-per-domain runbook (2026-07-07 §4.3) still applies to seeding and
  the ace counter.
- **`unmarkPaid` on Check-ins doesn't remove the cash-drawer line** (the confirm
  dialog tells the volunteer to pull it by hand). By design — the drawer is
  local to its own device and can't be reached from another. Fine as documented.
- **Push delivery is fire-and-forget `no-cors`** — "last push attempted" proves
  the request left the device, nothing more; the receipt is the public page
  updating (View live). Unchanged.
