### 2a. Off-site Operations Manager

The core structural finding: **the ops console is a single-authoritative-device
tool, but this persona is off-site coordinating multiple volunteer devices.**

- 🔴 FIXED — Public pages fetched Config / SeedBoardPublic / OpsStatus **once on
  mount** (only Matches + Aces polled), while admin copy promised "the site
  follows within ~1 min" (`Payments.jsx:179`, `Seeding.jsx:328`). A phone left
  open on the courts would never see the meter, draw lock/BYEs, or
  confirmation flips. *Fix: those tabs now re-poll every ~2 min; admin copy
  updated to match.*
- 🔴 FIXED — **False-BYE footgun**: field lock is a single boolean with no
  validation; locking with a half-built seed list published real-looking BYEs
  for merely-unfilled slots (`App.jsx:419-422`, `Seeding.jsx:314-326`).
  *Fix: locking now warns with a per-event count of registered entrants
  missing from the seed list.*
- 🔴 FIXED — The **"last push sent" indicator was a false-confidence signal**:
  it fired unconditionally when `fetch()` was *called* (`store.js:110`), not
  when anything was delivered — pushes are fire-and-forget `no-cors` with no
  retry, so a stale Apps Script or dropped connection looked identical to
  success. *Fix: relabeled "last push attempted" with an explicit
  spot-check-the-public-page hint. Delivery confirmation itself is backlog.*
- 🔴 MANUAL — **Apps Script redeploy state is invisible.** Committed handlers
  that silently no-op if the deployed script is older: `subscribe`
  (NotifyMe), `config`/`writeConfig_` (scholarship meter AND field lock),
  OpsStatus sentinel filtering, `seeds final` flag, `handleIdea_`
  (seed suggestions). See §4 action 1.
- 🟡 BY DESIGN (runbook) — **Check-ins, payments, walk-ups, merch inventory,
  partner overrides, and seed notes are localStorage-only** — invisible to any
  other device (`store.js:133-150`; Apps Script deliberately drops
  `participant`/`walk-up`, `ops-write-back.js:444-471`). An off-site manager
  cannot see who checked in or paid. Multi-device edits to synced surfaces are
  last-writer-wins: seeds pushes drop-and-replace the event
  (`writeSeeds_`), two ace counters overwrite each other (absolute totals),
  and the admin never reads Matches back, so two devices create divergent
  match ids → duplicate rows on the public board. *Mitigation now documented
  as the one-device-per-domain runbook (§4 action 3); real sync is post-event
  backlog.*
- 🟡 FIXED — `clearOps` read like a full reset but leaves everything already
  pushed (Matches, Aces, OpsStatus, Config) live on the public site
  (`AdminApp.jsx:186-190`). *Fix: dialog now says so explicitly.*
- 🟡 FIXED — Admin "View live" for Seeding deep-linked to the removed
  `#seeding` tab labeled "projected seeds" (`AdminApp.jsx:42`). *Fix: now
  points at `#brackets` / "public draws".*
- ⚪ Security posture is documented-as-intended: PIN `2311` and the write
  token ship in the bundle (deterrents only); the read token is correctly
  server-side; roster PII is allowlist-filtered at both boundaries with the
  gviz missing-tab fallback failing closed (`functions/api/sheet.js:40-99`).
  The owner's Zelle email ships in the effectively-public admin bundle
  (`Payments.jsx:43`). `idea`/`subscribe` are unauthenticated email/append
  endpoints (MailApp quota is the only rate limit).

### 2b. Varsity player (seeds, brackets, rules, format)

What already works well: compass draw and double-elim/Comeback Bracket are
fully explained with a correct bracket-reset rule; doubles scoring is fully
specified; suggest-the-seeds and find-yourself-in-the-draw are genuinely good;
no public "loser/losers" wording; committee data never *renders* publicly.

- 🔴 FIXED — **Committee joke notes about named players shipped in the public
  JS bundle**: the hardcoded `topSeeds` fallback (`App.jsx:359-374`) carried
  notes like "what's a backhand?", "Can't buy a second serve.", "Does he
  still play?". Never rendered, but plainly readable via view-source —
  against the site's own privacy contract for committee deliberation.
  *Fix: `topSeeds` deleted; seeds load exclusively from `SeedBoardPublic`.*
  The post-fix `dist/` grep caught a second copy: **`fallbackRoster` in
  `src/lib/sheet.js:99-103` carried the same joke bios** — and roster bios DO
  render publicly whenever the live roster fetch fails. *Fix: fallback bios
  blanked; the bundle grep in `docs/next-audit-handoff.md` guards both spots.*
- 🔴 FIXED — **Pre-lock draw contradiction**: the same fallback rendered
  named, seed-badged top-8 players while the intro said "Seeds and matchups
  are placeholders … TBD" (`App.jsx:922` vs `1554`). *Fix: same deletion —
  brackets are honest TBD until the committee publishes the board.*
- 🔴 FIXED — **Singles tiebreak format missing**: Rules gave "6-game no-ad
  sets" with no tie rule, while doubles specified its tiebreak exactly
  (`App.jsx:1874` vs `1861`). *Fix (interim): "a tied set is decided by a
  tiebreak (format confirmed at check-in)" — replace with the real rule, see
  §4 action 4.*
- 🟡 OPEN (procedure, not code) — **Seed order for 9+ leaks via bracket
  position**: hidden numbers, but `seedNamesFrom` places all names in
  deterministic seed-order slots (`App.jsx:403-416`), so a rank-12 entrant can
  infer their committee ranking from where they sit — and find-yourself
  pinpoints it. *Mitigation: committee shuffles the 9-16 and 17-32 order
  within bands before locking (§4 action 2).*
- 🟡 FIXED — Seeding methodology was absent from the Rules tab (only in the
  Brackets suggest-box blurb). *Fix: new "How are seeds decided?" FAQ.*
- 🟡 FIXED — Match guarantee phrased three ways ("3+", "at least 3 (up to
  5)", "multiple matches"). *Fix: unified on "at least 3 matches (up to 5)".*
- ⚪ "When do I play?" remains unanswerable pre-draw by design (times post
  with the draw; Day-of Schedule is labeled tentative). Fine — but publish
  the draw + times as early as possible.
- ⚪ Ace sponsor mechanics ($5/ace, $500 cap) exist only in code comments
  (`App.jsx:1209`), not public copy. Confirm and surface, or drop (§4
  action 4).
